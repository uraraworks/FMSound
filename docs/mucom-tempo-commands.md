# MUCOM88 テンポ関連コマンド(C / t / T)の意味

利用者実機報告「MUCOM88の新規作成の雛形がPMD雛形の半分くらいの速さに聞こえる」の
調査記録。2026-08-15。

## 結論

| コマンド | 意味 | 単位 | デフォルト | テンポか |
|---|---|---|---|---|
| `C` | 全音符あたりのクロック(分解能)指定 | クロック数 | C128 | **いいえ**(解像度) |
| `t`(小文字) | FM音源チップのタイマーBの数値を直接指定するテンポ指定 | TimerB生値 | - | はい(解像度依存) |
| `T`(大文字) | テンポ指定(1分間に演奏する4分音符の数で指定) | BPM相当 | - | はい(解像度非依存) |

## 出典

Open MUCOM88 Wiki「MMLリファレンス」
(https://github.com/onitama/mucom88/wiki/MML%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9、
2026-08-15にWebFetchで取得・確認)。

- `C`: 「全音符あたりのクロック(分解能)指定」。デフォルトC128。
- `t`: 「FM音源チップのタイマーBの数値を直接指定するテンポ指定」(用例: `t210`)。
- `T`: 「テンポ指定(1分間に演奏する四分音符の数で指定)」(用例: `T210`)。

package/readme.txt および upstream/MucomWeb/html/index.html にはMMLコマンド
リファレンス自体が無く(オンラインWikiへのリンクのみ)、upstream/MucomWeb/mucom88/src/
のMML解釈処理はコンパイラが古代祐三氏によるZ80機械語バイナリ(`bin_music.h`等に
埋め込み。CMucom::Compile()はこれをZ80エミュレータ上で実行するだけで、C/C++の
ソースにC/t/Tの解釈ロジックは存在しない)であるため、`grep`では見つからない。
上記Wiki出典に加え、`tools/verify_mucom_tempo_absolute.mjs`で実際にエンジンを
動かして数値で裏を取った。

## 実測検証(tools/verify_mucom_tempo_absolute.mjs)

- `T60`/`T120`/`T200`: 4分音符の実測実時間が理論値`60/T`秒の10%以内に一致
  (TimerBが8bit整数のため、BPMが高い=TimerB値が小さいほど量子化誤差が
  相対的に大きくなる。実測: T60=2.50%, T120=3.40%, T200=7.67%)。
- `C96/T120` と `C384/T120`: Tが同じならCを4倍にしても4分音符の実時間は
  ほぼ変わらない(relDiff=2.18%。Tは解像度非依存)。
- `C96/t200` と `C192/t200`: 同じtでCを2倍にすると4分音符の実時間もほぼ2倍になる
  (ratio=2.000。tは解像度依存)。
- [陽性対照] 「Cがテンポそのもの(反比例するはず)」という誤仮説をTを使わずに
  検証すると、実際の比はむしろ2.0(誤仮説の期待値0.5から大きく外れる)になり、
  誤仮説が明確に反証される。

## 不具合の実体

旧雛形(`MUCOM_NEW_MML_TEMPLATE`)は`C120`だけを指定し、テンポコマンド(`T`/`t`)を
一切書いていなかった。旧コメントは「Cはテンポ(4分音符基準のBPMそのまま)」として
いたが、これは実際には`T`(大文字)の説明であり、`C`には当てはまらない。
テンポ未指定のままドライバの既定値で再生されていたため、PMD雛形(`t60`=BPM120相当、
4分音符0.5秒)より遅く聞こえていた。

## 修正

`html/mucom-app.js` の `MUCOM_NEW_MML_TEMPLATE` に `T120` を追加した
(`A @78 T120 o5 l4 v10 cdefgab>c<`)。`T120`は4分音符=60/120=0.5秒で、
PMD雛形の4分音符0.5秒と実時間で一致する(基準[BPMの分母の音符]は違うが、
実時間は揃えてある。実測: mucom=0.5170s, pmd=0.5054s, 相対差2.30%)。
